# Logistic-regression descent paths

Run from the repository root:

```sh
python -m experiments.run_logreg_descent --noise 0 --output-dir results/logreg/descent/clean
python -m experiments.run_logreg_descent --noise 0.5 --output-dir results/logreg/descent/noisy
```

Each command writes two looping GIFs at 20 frames per second. Every optimizer
update is shown in order, with the actual training loss advancing on the right:

- `descent_2d.gif`: the two weights (w1, w2) move over contours of the exact
  uncorrupted mean training loss with bias fixed at zero.
- `descent_3d.gif`: the same weights and paths on the corresponding loss
  surface, with loss on the vertical axis and contours drawn underneath.

Bias stays zero throughout these runs. Every point completely describes the
trainable model state, and the 3D height is the same loss used to construct
both the surface and the 2D contours.

Growing trails and moving dots indicate update order; a black star marks the
common start. The counter is shared by both optimizers. R-SGD has a hollow
marker and an explicit label when it takes a zero step, so its pause is visible.
Both animations hold the final state briefly before looping. We do not mark an
alleged exact optimum. No PNGs are generated by this experiment.

## What the axes mean

In a contour plot, one point is one model state, not one data example.
The axes are weight values: x=w1 and y=w2. At (1, 2), the logistic model's
logit is a1 + 2*a2. We evaluate that model on all training examples
and average BCE to obtain its loss. A contour connects weight combinations
with equal loss at the specified fixed bias. In 3D, height is loss.

A general model can have many parameters, so a two-dimensional landscape
cannot show its entire objective. This visualization deliberately has only
two trainable parameters. The ordinary homework logistic model still trains
its bias; this experiment leaves its existing bias term out, which is exactly
equivalent to fixing it at zero.

## How the runs work

The experiment uses the existing `LogReg`, Gaussian sampler, loader factory,
`train()` and `RobustSGD`. A small optimizer subclass only records parameter
snapshots after each normal update. The zero bias is appended to saved snapshots
for clarity. Only the two weight gradients enter the optimizer and its
uncertainty estimate. No optimizer or trainer code is changed.

Both methods start from the same parameters and use the same data, batches,
learning rate schedule and gradient-noise random stream. SGD is RobustSGD with
rho=0; the other run uses rho=1 by default. Artificial noise is added to gradient
observations, not to the plotted objective or evaluation data.

Defaults: 500 training examples, 100 validation examples, 100 test examples,
batch size 32, 200 updates, initial learning rate 0.3, decay scale 50,
model/training seed 0, data seed 42. `--seed`, `--updates`, `--rho`, `--noise`
and `--output-dir` can be overridden. Other settings are ordinary function
arguments in `run_descent()`.

`sgd_trajectory.csv` and `rsgd_trajectory.csv` include the initial point and every
update: w1, w2, fixed zero bias, actual training loss, and the optimizer's zero-step
flag. `settings.json` records settings and final metrics. Losses at all snapshots
are evaluated together with PyTorch using stable BCE from logits.

These fixed-bias paired runs illustrate optimization paths; they are not a tuned,
multi-seed comparison. Stochastic losses need not decrease at every update, and
a robust zero step does not establish that a minimizer has been reached.
