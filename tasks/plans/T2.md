## Subtasks

### S1: Aggregate per-seed variability and track failed runs

**Code:** `experiments/grid_search.py` — `aggregate_metrics`, aggregated CSVs
for tuning/noise results, `failed_runs.csv`, safe execution in grid/noise
sweeps, variability metadata in `selection.json`.
**Tests:** `tests/test_grid_search.py` — sample-mean/std values for a known
group, failed run recorded and remaining points still selected, aggregated CSV
row counts.
**Docs:** README grid-search section — aggregated file names, sample-std
definition, and the meaning of `failed_runs.csv`.

**Spec:**
- Aggregate numeric metrics over seeds by group: tuning by
  `(method, learning_rate, rho)`, noise by `(method, learning_rate, rho,
  gradient_noise)`; write `<metric>_mean` and `<metric>_std` (sample std, n−1)
  plus `n_runs`.
- A tuning point with any failed seed is excluded from selection; every failure
  is recorded in `failed_runs.csv` with phase, parameters, seed, and error.
- Noise-sweep failures are recorded and the sweep continues; aggregated rows
  use only successful runs.
- `write_csv` accepts explicit field names so the failure table has a header
  even with zero failures.

### S2: Dataset-versus-training randomness study and CLI flags

**Code:** `experiments/grid_search.py` — optional `--data-seeds` study that
holds the training seed fixed and varies `data_seed` for selected parameters;
`experiments/run_grid_search.py` — `--data-seeds` and
`--data-sensitivity-seed`, mutually exclusive with `--data-seed`.
**Tests:** `tests/test_grid_search.py` — with two data seeds, verify fixed
training seed in every row and the aggregated file; CLI mutual exclusion.
**Docs:** README — how to read the two variability columns (fixed data seed
vs fixed training seed).

**Spec:**
- When `data_seeds` is supplied, the main grid uses its first value as the
  fixed dataset, so training-seed spread comes from one dataset.
- The sensitivity study runs both methods at their selected parameters for
  every data seed at every noise level of that method, using the fixed training
  seed and `save=False`; results go to `dataset_sensitivity.csv` and
  `dataset_sensitivity_aggregated.csv`.
- `--data-sensitivity-seed` defaults to the first seed; `--data-seed` and
  `--data-seeds` cannot be combined.
- Existing behavior without the new flags stays unchanged.

### S3: Explicit search budget

**Code:** `experiments/grid_search.py` — `search_budget` summary in
`selection.json` with run counts, update counts, and gradient-evaluation
counts for tuning, warmup, noise sweep, and dataset study.
**Tests:** `tests/test_grid_search.py` — exact counts for the tiny fake run,
and that failed runs are reported separately.
**Docs:** README — where the budget is stored and how it is counted.

**Spec:**
- Tuning runs/updates come from the completed grid points and their seeds;
  warmup cost is `2 × seeds × warmup_updates` updates with `batch_size`
  gradient evaluations per update.
- Noise and dataset-study counts come from their actual rows; use
  `row.get("gradient_evaluations", 0)` so lightweight test runners work.
- Include totals plus a separate `failed_runs` count.
